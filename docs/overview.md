# BarnCRM Overview

Applies to: BarnCRM main f69141c1c (landing batch L, with batch K). Pre-release: no package version exists yet; this tracks the newest code on main.

## What BarnCRM Is

BarnCRM is a free, open source suite of apps that installs into your organization's Salesforce account and turns it into a working database for people, households, gifts and more. It is built for small and medium organizations with one to ten Salesforce users and no full-time Salesforce administrator. The person who sets it up is an operations manager, development director or executive director who is comfortable with spreadsheets.

Three promises shape it:

- **The numbers are right.** Totals show when they were last calculated, so they never go quietly stale.
- **Upgrades are safe.** Nothing you configure is overwritten by a new version, and nothing has to be cloned to be used.
- **It is open.** The source is public, the software is free, and no data leaves your Salesforce org.

Every setting an administrator needs lives on a page inside the app (BarnCRM Settings), not only in Salesforce Setup. The few changes only Setup can make are listed where they matter, each with numbered steps and a button that opens the right Setup page. Settings are named in plain sentence case, the save bar says which changes are in the section you are on, and a panel that saves itself says so.

BarnCRM is in development. No package version exists yet and nothing is installable from a listing, so this page describes what is built on the main branch of the source code. It installs from source into Enterprise, Unlimited and Developer Edition orgs, Nonprofit Cloud included, with Platform licenses supported; Professional Edition and Platform Starter are not. A read-only pre-check tells you first whether your org has room: see [Installing BarnCRM](admin-guide/installing.md).

> **Not for production orgs:** BarnCRM is in pilot. We do not recommend installing pilot or testing versions in a production Salesforce org. Use a sandbox, a free Developer Edition org or a scratch org.

## Two Editions

Both editions include the full core suite of tools: people, households, relationships, addresses, importing with undo (an admin can create a new field for a column), Find, Super Transformer and bulk delete, duplicate review, Org Optimizer, Health Check, settings and the Setup Assistant.

| Edition | For | What you get |
|---|---|---|
| **Standard Edition** | Any organization on Salesforce, including businesses and clubs | BarnCRM Core alone. No nonprofit wording or module is shown. |
| **Nonprofit Edition** | Nonprofits (any organization may choose it) | Core plus the nonprofit tools: Giving first, then the other modules as you turn them on. |

You choose the edition once, in the first-run setup window; the Setup Assistant shows that answer. You can change it later: see [Editions](admin-guide/editions.md). A module you never install leaves nothing behind in your org.

## What an Org Gets Today

Install Core and run the Setup Assistant, and you can:

- Keep households and the people in them, with household names and greetings built for you and a warning when someone you are adding is already in BarnCRM, merge and split households, and record relationships, affiliations, addresses (including seasonal ones), several email addresses and a preferred phone. Each relationship, affiliation and address can be opened, edited or ended straight from its line on the person's page. An engagement score (off until turned on) rates each person from 0 to 100 every night from gifts, volunteer hours, event attendance and recent activity, weighted your way, and shows it as a meter on the person page.
- Bring in a spreadsheet (CSV or Excel) with a preview, matching rules and one-click undo, find and export records (including records within a number of miles of a postal code, and keep a search to run again), change many records at once (Find hands its search to Super Transformer), and delete many records with a way back, or archive old ones: save them to a file in Files, then delete them to free storage. Keep a copy of the records a saved search returns, whenever you want one, as Backup Sets saved to Files. Bring documents and attachments from another system into Files from a zip with a list of which record each belongs to, checked first and undoable.
- Review duplicates (and set up BarnCRM's recommended duplicate rules for people and households in one step, through the org connection), merge two records of any BarnCRM object with undo (Merge Records, off until turned on), check what needs attention in Org Optimizer (including Apex and flows on old API versions), document your fields, and the flows and Apex triggers that run on each kind of record, in a downloadable Data Dictionary, see which picklist values are still used, download an AI-Readiness Export pack for an AI tool you choose (BarnCRM never calls one itself), see who changed what in Setup long after Salesforce's 180 days, subscribe to BarnCRM's reports by email from one list, inspect every readable field of a record with the Record Inspector, keep the history of any fields you choose on BarnCRM's records beyond Salesforce's 20-field limit and restore an earlier value (Field History), see which BarnCRM setup uses a field before you retire it (Where Used), and run Health Check, with an Error Log that nothing fails silently into and that copies any entry as a bug report with no names or record values in it. Org Optimizer is the one home of Health Check and errors, with its sections listed like Settings (a Show box on a phone).
- Load data in bulk safely: when BarnCRM's automation fails on one record of a Data Loader, integration or import save, only that record is refused and the rest are saved; and let an integration user's or a migration consultant's saves skip automation (BarnCRM's and your own) while everyone else's run, all set on the Automation tab of the admin apps, which also lists your own flows with a switch and catches up afterwards with one button, and lists every automation in the org with whether Pause All covers it and how to make it, and can turn your own flows and validation rules off for a load, after saving a snapshot that Restore puts back exactly.
- Control who sees what with ready-made roles (BarnCRM Admin, Team Member and Read Only, each including what it needs in every installed module) and a short list of extra permissions that each work alone, see who can see or change what and why in Access Explorer (including a side-by-side compare of two people and a Modify All report), give or remove Read and Edit on fields across several permission sets at once with a preview and undo (Field Access Manager), load realistic sample data to try things out, and erase a person's personal data when you must.

Add Giving and you can also record and receipt gifts, split a gift across funds from its own page, run appeals and stewardship, get a task when it is time to ask a donor again, import gifts from NPSP or Nonprofit Cloud exports or from DonorPerfect, Bloomerang, Little Green Light, Neon, CiviCRM or Raiser's Edge NXT, and watch the Giving dashboard. Add Volunteers and you can schedule shifts and approve hours. Add Mirror to keep Opportunities and Campaigns in step, accept gifts from a giving page, or export gifts for accounting.

BarnCRM runs on Platform-only licenses, Sales and Service Cloud, an org with NPSP installed, and an org on Agentforce Nonprofit. In an org with NPSP, BarnCRM can adopt NPSP's existing households in place, with a preview and an undo, rather than create a second household for every family. BarnCRM's own Households feature waits until NPSP has stopped making households, so the two never both make one for the same person. When another app you are moving from is in the same org, the Integrations page in BarnCRM Settings offers Start Migration: the Migration Assistant then moves that app's records and setup into BarnCRM step by step, in order, with a preview, a check that the numbers match, undo, and a checklist of the old app's automations to switch off. It never changes the old app. The first kits copy DLRS and NPSP customizable rollups into Rollup Builder, adopt NPSP households and copy NPSP relationships, affiliations and household addresses, copy (with Mirror) Nonprofit Cloud relationships and links to organizations as relationships and affiliations, convert (with Mirror) Nonprofit Cloud households into BarnCRM households once and in place, with their members, never changing a Nonprofit Cloud record, and copy PMM programs, services, enrollments and service deliveries into Programs, copy Volunteers for Salesforce jobs, shifts, sign-ups and hours into Volunteers, and copy NPSP General Accounting Units, levels, recurring donations and engagement plans into Giving, with a parity report for levels, engagement plans and rollups, and (with Mirror) NPSP Campaigns, won Opportunities and soft credits as appeals, gifts and soft credits, and (with Mirror) Nonprofit Cloud campaigns, gift designations, gift commitments, paid gift transactions and gift soft credits as appeals, funds, commitments, gifts and soft credits, and copy Outbound Funds programs, requests, awards, disbursements and requirements into Scholarships and Outbound Grants; kits for the rest of NPSP, Nonprofit Cloud and Outbound Funds follow (built, not yet released).
Every tab in every BarnCRM app, Core and module, has its own icon.

An organization that works under several names can turn on brands (off by default): brand and
legal entity records, people and staff assigned to brands, a Brand field on gifts, appeals,
volunteer jobs, programs and portals, receipts printed and optionally numbered per brand,
volunteer letters, thank-you emails and portals in the brand's name, colors and sender, and an
option to share households, people and organizations only with the staff of their brands.


## Coming Next

This is the plan as recorded in the product plan (Section 6 and 6.0). Dates are not promised.

- **Finishing the Core quality pass.** Existing Core features are being tested, tightened and simplified before new modules start. Related-record duplicate matching (duplicate scan and import matching) is in progress.
- **Super Importer.** The import tool has one name everywhere (the tab, the page title, Data Jobs) and says "preview" and "kind of record" instead of "dry run" and "object". Its file steps show a dashed area to drop a file on, its commit button says how many rows it imports, and a finished import's **See Every Row** link opens all of its rows. Import grows in slices: the first (built, not yet released) reads several sheets of a workbook at once, maps headings that name the object and the field together, suggests the object from the file, and shows example values beside each column. The second (built, not yet released) loads several objects from one upload, a sheet for each or several on one row, linked and loaded parents first; it replaces the older related-records load. Closer heading matching follows.
- **BarnCRM Contact Point Sync.** An optional module, approved but not yet scheduled, for orgs that use Salesforce Contact Points: it keeps them in step with a person's email and phone and with their addresses, so Core itself never touches those objects.
- **BarnCRM Address Verification.** An optional module, approved but not yet scheduled, that verifies addresses with your own provider key (set in BarnCRM Settings) and records each address's verification status and date. No provider is bundled.
- **Programs and Logic Models.** Track programs, services, enrollments and attendance, and build logic models with indicators and a report you can send to a funder.
- **Funders.** A grant and funder pipeline with reporting deadlines and reminders, award schedules, restricted fund tracking and a deadline calendar (in progress).
- **Scheduled imports and connections.** On hold until the owner starts the next version.
- **Hardening, beta and listing.** Security review, scale testing, a beta with real organizations, then the Salesforce AppExchange listing and version 1.0.
