# v0.4 draft release notes: stewardship plans

Draft lines for the v0.4 release notes, written for Maria rather than for developers
(plan Section 7.5). Feature G-15 (stewardship plans), the NPSP Engagement Plans successor.

- **Write your follow-up down once.** A stewardship plan is a sequence your organization
  repeats: thank-you call this week, welcome packet next week, check-in in a month. Set the
  steps out once and Open Impact lays the tasks out every time the plan applies.
- **Plans can start themselves.** Choose what starts a plan: a donor's first gift, any gift,
  a gift over an amount you set, or a pledge or recurring gift becoming active. Or leave it
  manual and start it on a donor by hand.
- **Written down where you already work.** Plans live on the Stewardship plans page in
  Nonprofit Settings, under Giving. Write the plan, lay its steps out, put them in order and
  switch the plan on without opening Setup or hunting through object tabs.
- **Real tasks for real people.** A plan creates ordinary Salesforce tasks with real due
  dates, assigned to whoever owns the donor record, to whoever started the plan, or to one
  named person. Your team works them in the list they already use.
- **The same plan does not run twice on one donor.** While a plan is running for a donor,
  the same plan will not start again, so a donor who gives every month does not collect the
  same three tasks every month.
- **Open Impact never deletes a task it created.** Cancelling a plan marks the plan
  cancelled and leaves the tasks alone. A task is a record of somebody's work, and closing
  the leftovers is theirs to do.
- **A plan is laid out once, when it starts.** Editing a template afterwards does not reach
  back into plans already running: those tasks are already in people's lists and they have
  planned their week around them. The next plan to start picks up your edit.
- **Switchable like every other automation.** Turn stewardship off on the Automation page
  before a bulk import and the records load without starting hundreds of plans. Gifts and
  commitments have their own switches, so stopping one does not stop the other. Turning
  either back on does not catch up what it missed, which is deliberate: a welcome for a gift
  from three weeks ago is not a welcome.
- **A plan that cannot start never stops a gift being recorded.** If something goes wrong
  laying out a plan, the failure goes to the Error Log and the gift saves. A follow-up that
  did not happen is a smaller problem than money the organization lost track of.

## Stated plainly, what this release does not do

- **You close a plan yourself.** When a plan's last task closes, the plan stays Running
  until somebody marks it Complete. Closing it for you would mean Open Impact putting
  automation on the Task object, which it does not ship. The Running Plans list view shows
  what is still open.
