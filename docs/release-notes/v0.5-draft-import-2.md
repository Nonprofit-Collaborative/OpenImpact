# v0.5 draft release notes: undo an import, recurring files, Excel workbooks (C-19)

Written for Maria, to be folded into `v0.5.md` at the end of the iteration (plan Sections 7.4
and 7.5).

- **An import can be undone.** For 30 days after you commit an import, the Import tab lists it
  with an Undo button. Undo shows you how many people, households and organizations it would
  remove and how many changed values it would put back, and does nothing until you confirm
  that number. Deleted records go to the recycle bin.
- **Undo removes only what the import created.** A record the import matched or updated is
  never deleted. The values the import wrote to it are put back instead, unless somebody has
  changed them since, in which case their change is kept.
- **Undo keeps anything that has gained a life of its own.** A person the import created who
  has since had a gift, an affiliation, a relationship or an address recorded is kept, and so
  is their household. So is a household somebody else has joined, a record somebody has edited
  or logged an activity on since, and a record anything created since points at, from any
  object in the org. A record the check could not be run on, or that you cannot delete, is
  kept too. Each record kept is listed in the import's journal with the reason.
- **An undo the platform stopped part way can be run again.** It ends Undo failed, not Undone,
  and the Undo button comes back.
- **A dry run is refused once an import has been committed or undone.**
- **A dry run counts a new donor once.** A large file is read in parts, and a donor who is
  new and appears near the top and again near the bottom was counted as created twice in the
  dry run, although the commit creates them once. The dry run now counts them once, as the
  commit does, and remembers this on the rows themselves, so a dry run of a file of half a
  million rows runs in the same room as one of a thousand. Repeated gift external IDs are
  remembered the same way.
- **A new donor on several rows is created once.** A file with twelve monthly gifts from one
  new donor used to create twelve copies of them, each with a household of their own, when the
  rows were read together. The rows now share one person.
- **Imports from before this release undo only in part.** They did not mark the households
  they made or record the values they changed, so undoing one removes its people and
  organizations and puts no values back. Their households go only where the setting that
  deletes empty households removes them.
- **The Hub tracks files that arrive every month.** Tick **This file arrives regularly** on
  a mapping in the Import tab and name the source. The Nonprofit Hub home page lists every
  recurring source with the date it was last imported, so a file nobody has loaded this
  month stands out. Nothing is fetched or loaded automatically.
- **Import an Excel workbook directly.** Upload an .xlsx file as it is, with no need to save
  it as CSV first. The first sheet is read; dates arrive as dates and formulas as their
  values. Older .xls files still need saving as .xlsx or CSV, and so does a workbook too large
  to open in the browser (more than 500,000 rows or 1,000 columns).
- **A new setting: Days an import can be undone.** In Nonprofit Settings, Import. The default
  is 30 days, anything from 1 to 365 is allowed, and each import keeps the window it was
  committed with.
- **A new object: Import Journal.** It records the values each import changed on records you
  already had, and what each undo kept. Nonprofit Admin can read it; nobody edits it by hand.
