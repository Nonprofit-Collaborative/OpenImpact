# v0.4 draft release notes: addresses save in a person accounts org

Draft lines for the v0.4 release notes, written for Maria rather than for developers
(plan Section 7.5). Feature C-17 (addresses), defect found by the first test run against a
real org.

- **An address saves even when a household holds something that is not a person.** In an
  org that stores people as person accounts, Open Impact copies the default address into
  each household member's own mailing boxes. A member that is not a person, for example an
  organization added to a household by mistake, has no mailing boxes to copy into. Open
  Impact now leaves that member out and copies the address to everyone else. Before, the
  whole save was refused with "We could not copy this address to the standard address
  fields, so nothing was saved", which pointed at permissions and named nothing true.
- **The same is true of an address owned by a person.** If the person named on an address
  turns out to be a household or an organization record, the address still saves and the
  household's own billing address is left alone.

## Stated plainly, what this release does not do

- **Open Impact does not correct the household.** A member that is not a person is skipped,
  not moved or removed. Fixing the membership is still yours to do, and the Households page
  is where to do it.
