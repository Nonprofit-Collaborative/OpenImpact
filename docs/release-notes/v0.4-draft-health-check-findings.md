# v0.4 draft release notes: Three new Health Check findings (C-11, ADR-0024, ADR-0025)

Written for Maria, to be folded into `v0.4.md` at the end of the iteration (plan Sections 7.4
and 7.5).

- **Health Check now tells you if anyone can override the receipt lock.** Open Impact ships
  the **Override Receipt Lock** permission assigned to nobody: it is meant to be granted in
  Setup for one correction and taken away again. If it is still assigned, Health Check says so
  and names the people who hold it, so you can take it off the right permission set rather
  than go looking. It is amber, not red, because it may be assigned for a good reason right
  now. Leaving it assigned is the failure mode nothing else would ever mention again.
- **Health Check now compares your two fiscal years.** The fiscal year in Setup and **Fiscal
  Year Start Month** in Nonprofit Settings have to start in the same month: your donor totals
  are computed from the second and the retention reports (LYBUNT, SYBUNT, new versus retained,
  conversion) are filtered on the first. When they disagree, nothing errors, the reports simply
  disagree with the donor record until someone questions a year end number. The finding names
  both months and takes you to the setting.
- **Health Check now counts receipts that failed to generate.** A receipt number is used once,
  and a number handed to a document that never generated is recorded as a Void receipt with the
  reason "Generation failed". One of those is ordinary and is reported as information. More
  than one is amber: receipt generation is failing repeatedly, donors are waiting, and the
  button takes you to the Error Log entries that say why.
- **Nothing new to install or configure.** These are three more lines on the report you already
  have, and no object or field was added for them.
- **The Override Receipt Lock finding is an administrator question**, like the two access
  counts and the unread error count, because Salesforce only lets a person see their own
  access. Anyone without **Manage Nonprofit Settings** now sees three checks named as skipped
  rather than two.

**These findings work whether or not the Giving module is installed.** Core does not depend on
Giving (ADR-0009) and has to keep running on a Platform-only org (ADR-0013), so the permission
is looked up through the platform's own setup objects by name, and the receipts are counted
through a describe and a dynamic query. On an org with no Giving in it, the first finding
reports nobody and the third is not shown at all rather than reporting zero.

**No Apex in this repository has ever been executed**, here or anywhere else, so these three
checks compile and are covered by tests that have been written and not run.
