# v0.3 draft release notes: the other side of a relationship is written again (C-15 defect)

Written for Maria, to be folded into `v0.3.md` at the end of the iteration (plan Sections 7.4
and 7.5).

- **Relationships get both sides again, on an organization that has never changed a setting.**
  Record that Harper is Luis's spouse and Luis's record shows it, which is what the feature has
  always promised and what the admin guide has always said ships switched on. On a new
  organization it was not doing it: **Keep both sides of a relationship in step** was read as
  switched off before anybody had saved anything in Nonprofit Settings, so only the side that
  was typed was ever written, and nothing said so. Every other part of the feature ran: the
  duplicate check, the same person check, the status and date rules. Only the half that writes
  the other person's record was missing.
- **Saving an unrelated setting no longer switches a shipped feature off.** The console saves
  only what you change, and a setting nobody had touched could be stored as off on the way
  past. Settings that ship switched on are now carried into that first save.
- **What to check if you already used Nonprofit Settings.** An organization that saved its
  settings before this release has **Keep both sides of a relationship in step** stored as off.
  Open Nonprofit Settings, Relationships, and switch it on. Relationships entered while it was
  off stay one sided: open one from the person's card and enter the other side by hand, or
  re-save it once the setting is on.
