# v0.5 draft release notes: households, ready for any org

Draft lines for the v0.5 release notes, written for Maria rather than for developers
(plan Section 7.5). The household readiness pass over C-01, C-02, C-09 and X-09: the work
that makes households install cleanly, behave the same on every org shape, and leave
Nonprofit Cloud's own households alone.

- **Install picks the right way of belonging for you.** When Open Impact installs, it
  looks at the org and chooses: people stored as contacts get the simple model (a person
  belongs to one household), an org already using person accounts gets the flexible model
  (membership is its own record, so a person can be in more than one household). You can
  change it later in Nonprofit Settings, and the setting refuses to switch while the
  change would hide membership data you already have.
- **Health Check says when a setting no longer fits the org.** Two new findings:
  membership records that the current setting hides, and people stored as accounts while
  the setting expects contacts. The Hub home shows a count of install problems until they
  are dealt with.
- **A person's household is on the person.** Every contact page carries a Household panel:
  which household they belong to, the other members, and a Make primary button. Nobody
  has to know the difference between the two membership models to use it.
- **New household, from the Hub home.** One click opens a new household without a record
  type to choose or a name to invent: Open Impact fills in a placeholder and replaces it
  with the real name as soon as a member is added.
- **The household follows its members in the flexible model too.** Renaming, deleting or
  restoring a person now recounts and renames the household in both models. Before this
  pass the flexible model quietly did nothing on those three events.
- **Deleting an empty household is off until you say otherwise.** The setting shipped as
  on in the field definition and as off in the code. It now ships off everywhere, which
  is what the admin guide has always said, and the walkthrough shows what to expect.
- **Nonprofit Cloud households are recognized.** Open Impact can tell when an org has
  native household groups and reports how many. It does not create, rename, readdress or
  delete an account that Nonprofit Cloud manages as a household. (The four guards that
  enforce this are in this pass; see the Nonprofit Cloud households guide.)
- **Errors say what happened.** A household that cannot be created, a move the user has
  no permission to make, a merge that kept a custom name: each says so in plain words
  instead of a platform message or silence.
- **Screens keep up with themselves.** Save buttons disable while saving, spinners say
  what they are waiting for, and every icon-only button has a name a screen reader can
  read.

## Stated plainly, what this release does not do

- **It does not migrate Nonprofit Cloud households into Open Impact, or back.** One
  account has one household model. Migration in either direction, and any sync between
  them, is an owner decision recorded in plan Section 11.2 item 9.
- **It does not migrate data when you switch the membership setting.** The switch is
  refused while it would strand membership records; it does not move them. Plan Section
  11.2 item 10.
- **Professional Edition is not a target.** Owner decision, 2026-09-15.
