# v0.4 draft release notes: the Platform-only install claim, checked (C-01)

Written for Maria, to be folded into `v0.4.md` at the end of the iteration (plan Sections
7.4 and 7.5). Nothing here changes anything you can see in the app. It is here because it
concerns a promise the product makes about where it can be installed.

- **Open Impact still says it installs on a Salesforce org with no extra clouds, and that
  claim now has evidence behind it.** The aggregation engine Open Impact carries inside
  Core brings its own test classes, and those name a handful of Salesforce objects the
  project does not otherwise use. If any of them were missing from a plain org, Core would
  have refused to install at all, silently, until somebody tried it. All of them are
  present. No behavior changed and no code was rewritten: the point is that the question is
  now answered rather than open.
- **A new build check keeps it answered.** Every Salesforce object Core and the modules are
  allowed to name is now written down in one place, and the build fails on any object that
  is not on that list, including one arriving with a future upgrade of the engine. The
  previous check could only fail on names somebody had thought to forbid.
- **Still to do, and said plainly:** the full test suite has never been run against an org
  of that shape. Until it has, this is strong evidence rather than proof. See
  `packages/core/vendor/apex-rollup/VENDOR.md`.
