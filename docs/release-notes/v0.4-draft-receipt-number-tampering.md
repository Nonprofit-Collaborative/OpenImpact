# v0.4 draft release notes: A receipt number comes only from the sequence (G-13, ADR-0033)

Written for Maria, to be folded into `v0.4.md` at the end of the iteration (plan Sections
7.4 and 7.5).

- **Receipt Number on a gift is now read only for everyone.** It was editable for Giving
  Staff and Giving Admin, which meant anyone entering gifts could type a receipt number onto
  one. Open Impact issues receipt numbers itself, from the counter in Nonprofit Settings,
  when it creates the receipt.
- **A number that was typed in did real damage, which is why this changed.** It belonged to
  no receipt, so there was no PDF and nothing to send. It locked the gift's amount, date and
  donor as though a donor were holding a document. The same number could still come out of
  the counter later and appear on somebody's year-end statement, which is the one outcome
  receipt numbering cannot recover from. And that gift could never be receipted afterwards,
  because Open Impact saw a number already there.
- **The save is refused wherever it comes from.** The record page, a list view, an import, an
  integration, and creating a gift with the number already filled in are all refused with "A
  receipt number is issued by Open Impact when it creates the receipt, and cannot be filled in
  by hand." Click **Issue receipt** on the gift instead.
- **Issuing, voiding and reissuing are unchanged.** Everything the Receipts feature does
  still works exactly as before, for the same people, and nobody needs a new permission to
  issue a receipt.
- **Recovering a gift that already carries a stray number, and importing legacy numbers,
  still work, through the documented override.** A user holding **Override Receipt Lock** can
  set or clear a receipt number, and the temporary permission set now also has to grant Edit
  on Gift Receipt Number. Both steps are on the [Gifts page](../admin-guide/gifts.md), under
  "Lifting the receipt lock". Every use is still written to the Error Log at Warning severity.
- **For builders.** `GiftService.recordReceiptNumbers` is the only door to the field. It now
  names the gifts it is renumbering, by Id, rather than lifting the rule for the whole
  transaction, so the allowance cannot reach an unrelated gift saved in the same save. The
  write moved to `GiftReceiptNumberWriter`, a system-mode writer under ADR-0021, because a
  field nobody may edit cannot be written in user mode.

Read [Receipts](../admin-guide/receipts.md), section "Common mistakes", and
[Gifts](../admin-guide/gifts.md), section "Lifting the receipt lock".
