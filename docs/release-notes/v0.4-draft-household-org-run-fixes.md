# v0.4 draft release notes: Two household fixes the first org run surfaced (C-01)

Written for Maria, to be folded into `v0.4.md` at the end of the iteration (plan Sections 7.4
and 7.5).

- **Merging two households always leaves you with a household.** If both households happened
  to have nobody in them, the settle-up that runs after a merge treated the surviving
  household as one somebody had been the last to leave and tidied it away, so a merge could
  end with no household at all and everything the other one carried in the recycle bin with
  it. "Delete a household when the last person leaves" is about a household somebody left,
  never about the one you chose to keep, and the merge now says so.
- **Organizations no longer carry a member count of zero.** Member Count is a household
  number: it is computed for households and deliberately never written to an organization.
  The field nonetheless shipped with a default of zero, so every organization in the org
  reported "0 members" in reports and through the API. The default is gone, and an
  organization's Member Count is simply empty. Household member counts are unchanged: they
  are written by the same upkeep as before, on every membership change.
- **Nothing to install or configure.** No object was added and no setting changed.
