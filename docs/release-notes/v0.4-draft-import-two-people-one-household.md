# v0.4 draft release notes: a row with two people in it is one household (C-14)

Written for Maria, to be folded into `v0.4.md` at the end of the iteration (plan Sections 7.4
and 7.5).

- **A couple on one line of your file becomes one household with both of them in it.** Map
  the second person's columns to Contact 2 and the two people are put in the same household,
  whichever way your org keeps membership and whether your people are contacts or person
  accounts. Before this fix, an org set up the way Open Impact recommends (Nonprofit Cloud,
  where people are accounts and membership is a Household Member record) got two households
  from that row, or one household and a second person with no household at all. An org that
  keeps people as contacts and uses Household Member records got the same wrong answer for
  the same reason: the importer joined the second person the way the older, simpler
  membership setting does, and in that setting the join it wrote meant nothing.
- **The household is named from your file when you map a name for it.** Map a column to
  Household: Name and that name is used and kept, because a name you typed is a name you
  chose: the household naming patterns will not rewrite it afterwards. This now holds
  whichever way membership is stored.
- **An import still never moves somebody who is already in your org.** If the second person
  on a row matches a person you already have, they keep the household they belong to today.
  Only people the import creates are joined to the row's household.
- **A row that names only a second person still gets a household.** Nobody is left without
  one.
- **Nothing to install or configure.** No object was added, no field was added and no
  setting changed. Imports you have already run are not revisited: a household that came out
  split can be put right from the household page, with Merge or split.
