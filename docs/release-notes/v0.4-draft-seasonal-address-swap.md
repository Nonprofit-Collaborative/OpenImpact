# v0.4 draft release notes: Seasonal address swap (C-18)

Written for Maria, to be folded into `v0.4.md` at the end of the iteration (plan Sections 7.4
and 7.5).

- **Winter addresses move themselves.** An address marked Seasonal now becomes the address in
  use on the day its season starts, and the address it replaced comes back on the day the
  season ends. A range that crosses New Year, such as November 1 to March 31, is one season:
  the household is in Arizona on Christmas Day and back home on April 1.
- **You can see that the job ran.** The Nonprofit Hub home page and the Addresses page of
  Nonprofit Settings both show when the swap last finished and what it did, in one sentence:
  how many households moved to a seasonal address, how many moved back, and how many could
  not be changed. If the job is switched on and has not run in more than 36 hours, the Hub
  says so.
- **You switch it on from the app, not from Setup.** Nonprofit Settings, Addresses, Schedule
  the nightly swap. There is also a Run the swap now button, so you can prove it works
  without waiting until tomorrow.
- **A household that cannot be moved does not stop the rest.** Anything that fails goes to the
  Error Log with the household named, and the run carries on. Two seasonal addresses covering
  the same day is a data entry mistake, and it is reported rather than picked silently: the
  address added first wins.
- **Nothing is deleted and nothing is guessed.** The address a season replaced is marked so
  the job knows exactly which one to put back, rather than working it out again in the spring.

Read [the admin guide page](../admin-guide/addresses.md) for the five-minute walkthrough that
proves the swap works before the winter mailing goes out.
