# v0.5 draft release notes: Core fixes from the first full test run in an org

Draft lines for the v0.5 release notes, written for Maria rather than for developers
(plan Section 7.5). Core's Apex tests ran in a persistent org (Enterprise Edition, person
accounts on, Giving installed) for the first time; these are the product defects that run
found, and what changed.

- **The person who installs Open Impact gets access again.** The install gives the
  installer the Nonprofit Admin permission set and role. Salesforce refuses to save those
  in the same step as the ordinary records the install also writes, so on a fresh org the
  installer could be left without access and only an Error Log entry to show for it. The
  access is now given by a background job that runs as soon as the install finishes.
- **Giving a colleague a role from the Setup Assistant works.** Step four gave the role and
  recorded the step in one save, which Salesforce refuses for the same reason. The page now
  records the step separately, straight after the role is given.
- **Saving one setting no longer decides others for you.** The first time anything was
  saved in Nonprofit Settings, Salesforce filled every other setting that has a default,
  which confirmed a coexistence mode, chose a way of belonging to a household, and ticked
  Setup Assistant steps nobody had taken. The first save now changes only what you saved.
- **Switching one automation off saves.** The Automation page could not save a switch for
  anyone who held only the Nonprofit Admin permission set.
- **A household kept for Nonprofit Cloud's sake is reported once.** Moving somebody out of
  a household that Nonprofit Cloud also uses leaves it in place, as before, and the Error
  Log now says so once rather than twice.
- **Sample data loads in orgs with duplicate rules.** The standard duplicate rules most orgs
  have switched on alerted on the sample people and stopped the load part way through.
  Sample data now saves past a rule that only alerts; a rule set to block still blocks.
  The Connections count on the sample data card counts each connection once, as the admin
  guide describes, rather than once for each side.
- **Importing people as person accounts no longer trips over the Name column.** A person
  stored as an account is named by their first and last name; a column mapped to Name is
  left to those.
- **Nothing to install or configure.** No object, field or setting was added.
