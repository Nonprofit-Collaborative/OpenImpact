# v0.5 draft release notes: fixes from the second full test run in an org

Draft lines for the v0.5 release notes, written for Maria rather than for developers
(plan Section 7.5). Core and Giving ran their Apex tests together in a persistent org
(Enterprise Edition, person accounts on, Sales Cloud); these are the product defects that
run found, and what changed.

- **Rollup totals are calculated.** Total giving, gift counts, soft credit totals and the
  other rollups on the Rollups page were handed to the calculation engine without the names
  of the objects and fields they read and write, so a save logged an error instead of
  updating the total, and a Recalculate wrote nothing. They are now calculated as the page
  describes, including after a refund or a write-off.
- **Receipts are issued on orgs with no community or portal users.** Storing the receipt
  document asked Salesforce to limit the file to internal users, which Salesforce refuses on
  an org that has no external users at all, so no receipt could be issued there. The file is
  now limited to internal users where that means something and left to the receipt and gift
  that govern it everywhere else. Who can open a receipt has not changed.
- **Fundraisers can save gifts that read a setting.** A save that looked up a Nonprofit
  Settings value failed for users who had not been given access to the list of settings
  itself. That list ships with Open Impact and holds no data, and is now read for everyone.
- **Removing Giving sample data works when a sample gift was refunded.** The refund is now
  removed before the gift it reverses, which is the order the refund rule asks for.
- **A donor whose gift was refunded in full shows a total of zero.** Their total giving and
  soft credit total were left blank, because the calculation engine reports a sum that
  comes to exactly zero as "no value" unless told otherwise, and then leaves a blank field
  blank. Every total now reads zero when the gifts and their refunds cancel out, which is
  what the refund rule says. Counts, largest gift and the other rollups are unchanged.
- **Nothing to install or configure.** No object, field or setting was added.
