# v0.5 draft release notes: gift import and donation matching

Draft lines for the v0.5 release notes, written for Maria (plan Section 7.5). Features G-23
and G-24.

- **Gift files now load gifts.** The generic gift list, and any mapping with gift columns,
  creates real gifts through the **Import** tab: the donor, the amount and date, the payment
  method, the appeal, the fund or a split across several funds, a soft credit and an in honor
  or in memory tribute. Every gift goes through the same checks as a gift typed by hand.
- **Load a file twice, get the gifts once.** Map the processor's transaction number to
  **Gift: external ID** and a second load of the same file matches instead of duplicating.
- **Gifts find the pledge they pay.** Donation matching links an imported gift to the donor's
  scheduled pledge or recurring payment within a date window and an allowed amount difference,
  so balances go down on their own. Each mapping chooses **Match or create**, **Always
  create**, **Match only** or **Never match**; the defaults are in **Nonprofit Settings**,
  **Import**. Donation matching's choice, date window and allowed difference are
  kept from the dry run, so the commit matches under them even if they are changed in between.
- **Control totals.** Type the row count and the total from the deposit slip before a dry
  run; the dry run checks them and a commit waits until they agree.
- **Undo keeps what a donor holds.** Undoing a gift import removes its gifts first, but keeps
  any gift a receipt or a year-end statement lists, and the donor of any gift it keeps, each
  with the reason in the journal.
