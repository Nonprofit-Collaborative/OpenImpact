# Integration notes: C-14 (import framework)

For the integrator. This branch touches no `permissionsets/*` file. Everything the permission
sets need from the import framework is listed here, together with the decisions a reviewer
should see before they read the code.

### Nonprofit_Staff

Read on `Import_Batch__c` and `Import_Row__c`, with read on the fields listed above, and read
on `Account.Created_By_Import_Batch__c` and `Contact.Created_By_Import_Batch__c`. Read is
enough: `ImportController.getRecentBatches` and `getBatch` are deliberately outside the
permission gate so a colleague can watch a long import without holding the administrator's
permission. Everything that writes is gated on `Manage_Nonprofit_Settings`.

Staff should not get the `Import` tab: the wizard tells them they lack the permission, which
is a worse experience than not offering it.

### Nonprofit_Read_Only

Read on `Account.Created_By_Import_Batch__c` and `Contact.Created_By_Import_Batch__c` only, so
a report can say where a record came from. No access to the import objects themselves.

### Giving package

`Gift__c.Created_By_Import_Batch__c` is added by this branch and belongs in the Giving
permission sets alongside the rest of `Gift__c`: read and edit for `Giving_Admin` and
`Giving_Staff`, read for `Giving_Read_Only`.

## 3. Decisions a reviewer should see

- **Gift columns are staged, not loaded.** Core resolves `Organization`, `Household`,
  `Contact1` and `Contact2`. `Gift`, `Allocation`, `SoftCredit` and `Affiliation` belong to
  packages Core may not reference (ADR-0014), so `ImportRowProcessor` offers each chunk to an
  optional `ImportEntityProcessor` implementation found by `Type.forName` under the well-known
  name `GiftImportProcessor` (the mechanism in ADR-0017). None ships yet. Where none is
  installed the columns stay on the staged row, the run log says so in one line, and no row is
  rejected for carrying one. This is recorded in canonical model R-IR6, which this branch adds,
  and stated plainly in the admin guide's "Common mistakes". A Giving-side implementation is
  the natural home for the gift half of the shipped "Generic gift list" template.
- **The External ID matching rule uses the object's own external identifier field**, resolved
  by describe (`isExternalId()`), rather than a new field invented for the importer. An org
  with no external identifier field gets a run log line saying so and no matches, which is
  better than silently creating duplicates. Worth a second opinion at review.
- **Person Accounts.** `ImportTemplateService.defaultPersonMode` proposes the mode from
  `OrgShapeDetector`, and `ImportBatchService.start` refuses a run whose template asks for
  person Accounts in an org that has none, with a message naming the fix. The write path
  builds the Account with `put()` on field names held as text, so Core still compiles and
  deploys on a Platform-only org. **This path has never been executed**: there is no org here,
  and no person-account org at all. Treat it as unverified.
- **Two system-mode writes**, both under ADR-0021 and both over fields the package owns:
  `ImportRowProcessor.writeBack` (the staged rows must record what happened even where the
  running user cannot edit them) and `ImportBatchService.finish` plus
  `ImportProcessorBatch.rejectChunk` (the same, from a batch context). Everything that touches
  an Account or a Contact runs in user mode.
- **`File_Id__c` is populated only for files under about 4 MB.** The component sends the
  original to `ImportController.saveFile` so it can be downloaded again (canonical model
  Section 16), and skips it above that size rather than risking the request heap. A larger file
  still imports. The field is therefore not required in metadata even though the canonical
  model marks it required, and that is the one place the build is narrower than the model.
- **CSV only in v1.** The plan names SheetJS and XLSX. Vendoring a spreadsheet library is a
  separate decision with its own licence and size questions, and the admin guide says CSV
  throughout, so this branch parses CSV in the browser with about a hundred lines in
  `lwc/importWizard/csv.js` and nothing vendored. XLSX is the obvious next increment.
- **Undo is not built** (R-IB6). `Undo_Deadline__c` is written on commit so the window is known
  from the first batch, and C-19 in v0.5 does the rest.

## 5. What could not be verified

There is no Salesforce org in this environment, so **no Apex test has been executed and no
metadata has been deployed**. The Apex compiles cleanly under `check-apex-offline.sh`, which
catches syntax, type and unknown-class errors but not unknown SOQL fields; every query was read
by eye against the object folders. The Jest tests and every static check pass. The Apex tests
are written and are unverified.
