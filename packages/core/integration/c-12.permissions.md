# C-12 permission requirements

What the guided Setup Assistant needs in each packaged permission set, on top of what
`c-03.permissions.md` already lists. C-12 ships no permission set files: the integrator
merges these entries into `Nonprofit_Admin`, `Nonprofit_Staff`, and `Nonprofit_Read_Only`.

The assistant runs the same permission gate as the settings console: reading is open to
everyone who can open the Hub, and every save checks the `Manage_Nonprofit_Settings` custom
permission (created by C-04) through `FeatureManagement.checkPermission`.

## Nonprofit_Admin

| Kind | Entry | Why |
|---|---|---|
| Apex class | `SetupAssistantController` | Every panel of the assistant calls it. |
| Apex class | `ModuleDetectionService` | Step three, six, seven, and eight ask it what is installed. |
| Field | `Setup_Steps_Skipped__c` on `Nonprofit_Settings__c` | Read and Edit: a skipped step is remembered. |
| Field | `Setup_Started_At__c` on `Nonprofit_Settings__c` | Read and Edit: how long setup took. |
| Field | `Default_Fund__c`, `Default_Appeal__c` on `Nonprofit_Settings__c` | Read and Edit: step three, written only when Giving is present. |
| Field | `Organization_Legal_Name__c`, `Organization_EIN__c`, `Organization_Address__c`, `Receipt_Logo_Document_Id__c`, `Receipt_Signature_Document_Id__c`, `Receipt_Signer_Name__c`, `Receipt_Signer_Title__c` | Read and Edit: step five, and the Organization section of the settings console. |
| Object | `ContentDocument`, `ContentVersion`, `ContentDocumentLink` | Create and Read: step five uploads the logo and the signature. Standard file access, no extra object. |
| Object | `User` | Read: step four picks a person with a record picker. |

## Nonprofit_Staff

| Kind | Entry | Why |
|---|---|---|
| Apex class | `SetupAssistantController`, `ModuleDetectionService` | The assistant has to load; saving is refused by the permission check, not by class access. |
| Field | every `Nonprofit_Settings__c` field above | Read only. David reads how the org is set up and cannot change it. |
| Object | `ContentDocument`, `ContentVersion` | Read only: the upload controls are not rendered without the permission. |

## Nonprofit_Read_Only

Same as `Nonprofit_Staff`, with nothing writable anywhere.

## Notes for the integrator

- **Custom permission gate.** `SetupAssistantController` checks `Manage_Nonprofit_Settings`
  on `completeStep`, `skipStep`, `reset`, `applyCoexistence`, `saveOrganizationIdentity`,
  `saveDefaults`, and `assignAccess`. `getState` is open, so David sees the same eight steps
  with a notice naming the permission he is missing.
- **Field level security is what actually governs saving.** The identity values go through
  `SettingsService`, which writes `Nonprofit_Settings__c` in user mode, so the fields above
  have to be editable on the admin set for step five to work.
- **Uploads.** Step five uses `lightning-file-upload`, which requires a record to attach the
  file to. There is no record a logo belongs to, so it attaches to the current user's own
  record and only the `ContentDocumentId` is stored in settings. Standard file permissions
  therefore apply, and the file belongs to whoever uploaded it. The admin guide says so.
- **Integration points this branch stubbed rather than shipped**, all owned by other
  features. Each one is called defensively (a failure costs the panel its data, not the
  page), except the two marked required:
  - `ErrorLogger.log(Exception, String)` (C-05).
  - `OrgShapeDetector.detect()` returning `OrgShape` with `hasPersonAccounts`, `hasNpsp`,
    and `hasIndustriesNonprofit` (C-07 and C-11). Step one degrades to the fresh org case if
    it throws.
  - `CoexistenceService.getCurrentMode()` and **`CoexistenceService.applyMode(String)`**
    (C-07, required). `applyMode` is the one method C-12 needs that the brief did not list:
    confirming a mode has to put that mode in force, and `applyRecommendedIfUnset()` cannot
    express "Maria chose a different one". C-07 owns the implementation.
  - `AccessService.getRoles()` returning role developer names, and
    `AccessService.assignRole(Id, String)` (C-06, required for step four). The assistant
    renders each developer name with its underscores replaced by spaces; when C-06 ships
    labelled roles, step four should use those labels instead.
- **Setting Definition rows.** C-12 ships seven rows in a new **Organization** section of the
  settings console, so everything step five writes is also editable later on the settings
  page. `Default_Fund__c` and `Default_Appeal__c` deliberately have no rows: a console row
  would have to name the Giving objects, which Core may not do. Giving ships those rows in
  v0.2 when Fund and Appeal exist.
