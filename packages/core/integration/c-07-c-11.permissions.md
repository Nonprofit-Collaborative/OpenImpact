# C-07 and C-11: what the packaged permission sets need

Features C-07 (coexistence mode with automatic detection) and C-11 (Health Check v1) ship no
permission set files of their own: the packaged permission sets are one shared file set and
are owned by the access feature (C-06). This page lists what those sets must grant for these
two features to work, plus the contracts this branch assumed and the assumptions that need
confirming.

## Apex class access

| Class | Nonprofit_Admin | Nonprofit_Staff | Nonprofit_Read_Only |
|---|---|---|---|
| `HealthCheckController` | yes | yes | yes |
| `HealthCheckService` | yes | yes | yes |
| `CoexistenceService` | yes | yes | yes |
| `OrgShapeDetector` | yes | yes | yes |
| `OrgShapeSelector` | yes | yes | yes |
| `UserAccessSelector` | yes | yes | yes |
| `ErrorLogCountSelector` | yes | yes | yes |

Everyone gets read access to the report. That is deliberate (admin guide, "How to turn it
on"): anyone who can open the Nonprofit Hub can read Health Check and tell an administrator
what it says. Acting on a finding is gated separately, by custom permission, inside
`HealthCheckController`, so class access alone grants nothing dangerous.

`@AuraEnabled` methods still require class access on the running user's profile or permission
set, so all three sets need every class in the table, not only the controller.

## Custom permission

| Custom permission | Nonprofit_Admin | Nonprofit_Staff | Nonprofit_Read_Only |
|---|---|---|---|
| `Manage_Nonprofit_Settings` | yes | no | no |

`HealthCheckController.applyRecommendedMode` and `applyJunctionMembership` check it with
`FeatureManagement.checkPermission` and throw `AuraHandledException` with the label
`Core_HealthCheck_PermissionRequired` when it is missing. The component hides the Fix buttons
for the same users, from `Report.canManageSettings`.

## Permission set groups the access checks read

C-06 owns these. Health Check queries them by developer name and never creates or changes
them.

| Group developer name | Label | Contains | Counted as |
|---|---|---|---|
| `Nonprofit_Admin_Group` | Nonprofit Admin | `Nonprofit_Admin` | administrator, and access |
| `Fundraising_Staff` | Fundraising Staff | `Nonprofit_Staff` | access |
| `Program_Staff` | Program Staff | `Nonprofit_Staff` | access |
| `Volunteer_Coordinator` | Volunteer Coordinator | `Nonprofit_Staff` | access |
| `Read_Only` | Read Only | `Nonprofit_Read_Only` | access |

Two findings use them. "No one is assigned the Nonprofit Admin role" counts active people in
`Nonprofit_Admin_Group` plus anyone holding the `Nonprofit_Admin` permission set directly.
"N users cannot see the app" counts active standard users who are in none of the five groups
and hold none of the three packaged permission sets directly.

## Object and field access

Nothing new. These features read `Nonprofit_Settings__c` (through `SettingsService`),
`Error_Log__c` (a count of rows with status New), `User`, and `PermissionSetAssignment`.
`User` and `PermissionSetAssignment` are readable by all standard users, and the queries run
`WITH USER_MODE`, so a user who cannot see them gets that one check reported as failed rather
than a broken page.

## Lightning component

`healthCheckPanel` is exposed to `lightning__AppPage` and `lightning__HomePage`. It belongs on
the Nonprofit Hub home page next to the Setup Assistant, and in the settings console under the
Health section (`Setting_Definition.Health_Check` names it as its component).

## Contracts this branch consumed

| Contract | Owner | Used as |
|---|---|---|
| `SettingsService.getSettings()` | C-03 | Returns `Nonprofit_Settings__c` with `Coexistence_Mode__c`, `Household_Membership_Mode__c`, `Automation_Paused_Until__c`. |
| `SettingsService.saveValues(Map<String, Object>)` | C-03 | Keys are custom setting field API names, for example `Coexistence_Mode__c`. Writes are audited by that service, so nothing here writes the custom setting directly. |
| `ErrorLogger.log(Exception, String)` | C-05 | Second argument is a plain-language context, here the label `Core_HealthCheck_ErrorContext` ("Health Check"). |
| `Error_Log__c` | C-05 | Read only, `Status__c = 'New'` counted. |
| `Setting_Definition__mdt` | C-03 | Three records shipped: `Coexistence_Mode`, `Household_Membership_Mode`, `Health_Check`. |
| Permission set groups | C-06 | Queried by `DeveloperName`. |

## Assumptions to confirm

1. **Permission set group developer names: confirmed with C-06.** The access checks read the
   five groups C-06 ships, listed above. `GROUP_ADMIN` is `Nonprofit_Admin_Group`. A direct
   assignment of the `Nonprofit_Admin` permission set counts as an administrator too, and a
   direct assignment of any packaged permission set counts as access, so a person set up by
   hand rather than through the Access page is not reported as locked out. If a group is
   renamed, the constants at the top of `HealthCheckService` are the only place to change.
2. **`Setting_Key__c` holds the custom setting field API name**, for example
   `Coexistence_Mode__c`, which is what `SettingsService.saveValues` takes as a map key. The
   `Health_Check` record is a component, not a stored value, so its key is `Health_Check`.
3. **Settings console sections.** Fix targets that are not actions or URLs name a section:
   `General`, `Households`, `Access`, `Automation`. If the console names its sections
   differently, the constants at the top of `HealthCheckService` are the only place to change.
4. **Connect marker class.** The Connect module is detected with
   `Type.forName('ConnectService')`. Connect must ship a class of that name (v0.6) or the
   informational finding will keep appearing after Connect is installed.
5. **Fix target shapes.** The component tells the three kinds apart by shape: `action:` prefix
   means a controller method, a leading `/` means navigate, anything else is a settings
   section. Any new finding must follow that convention.
6. **Shipped description text.** The descriptions in the custom metadata records are wrapped
   across lines by the repository's Prettier XML settings. The settings console should render
   them with whitespace collapsed, as HTML does.
