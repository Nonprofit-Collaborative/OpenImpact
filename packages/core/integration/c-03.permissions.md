# C-03 permission requirements

What the Nonprofit Hub and the Nonprofit Settings console need in each packaged permission
set. C-03 ships no permission set files: the integrator merges these entries into
`Nonprofit_Admin`, `Nonprofit_Staff`, and `Nonprofit_Read_Only`.

The custom permission `Manage_Nonprofit_Settings` is created by C-04. C-03 only reads it,
through `FeatureManagement.checkPermission`.

## Nonprofit_Admin

| Kind | Entry | Why |
|---|---|---|
| Application | `Nonprofit_Hub` (visible) | The app Maria works in. |
| Tab | `Nonprofit_Hub_Home` | Visible |
| Tab | `Households` | Visible |
| Tab | `Organizations` | Visible |
| Tab | `Nonprofit_Settings` | Visible |
| Tab | `Error_Log__c` (C-04) | Visible: the Hub error tile links to it. |
| Custom permission | `Manage_Nonprofit_Settings` | Without it the console is read only. |
| Apex class | `SettingsController` | The console's controller. |
| Apex class | `HubController` | The home page's controller. |
| Apex class | `SettingsService` | Called by both controllers. |
| Apex class | `SetupAssistantService` | The setup checklist. |
| Apex class | `SettingDefinitionSelector` | Reads the shipped console rows. |
| Apex class | `SettingChangeSelector` | Reads the audit list. |
| Apex class | `HubErrorCountSelector` | Counts errors for the Hub tile. |
| Object | `Nonprofit_Settings__c` (C-04) | Read, Create, Edit: the console writes the org defaults in user mode. |
| Field | every `Nonprofit_Settings__c` field a console row edits, plus `Setup_Steps_Completed__c` | Read and Edit. |
| Object | `Setting_Change__c` (C-04) | Read, Create: one audit record per changed setting, and the Recent changes list. |
| Field | `Setting_Name__c`, `Old_Value__c`, `New_Value__c`, `Changed_By__c`, `Changed_At__c` | Read and Edit. |
| Object | `Error_Log__c` (C-04) | Read: the Hub tile counts records with status New. |
| Field | `Status__c` on `Error_Log__c` | Read. |

## Nonprofit_Staff

| Kind | Entry | Why |
|---|---|---|
| Application | `Nonprofit_Hub` (visible) | Staff work in the same app. |
| Tab | `Nonprofit_Hub_Home`, `Households`, `Organizations`, `Nonprofit_Settings` | Visible. The Error Log tab is not on this set. |
| Custom permission | none | David sees the read-only console that names the permission (C-03 acceptance criterion). |
| Apex class | `SettingsController`, `HubController`, `SettingsService`, `SetupAssistantService`, `SettingDefinitionSelector`, `SettingChangeSelector`, `HubErrorCountSelector` | The pages have to load; saving is refused by the permission check, not by class access. |
| Object | `Nonprofit_Settings__c` | Read only. |
| Field | every `Nonprofit_Settings__c` field a console row shows, plus `Setup_Steps_Completed__c` | Read. |
| Object | `Setting_Change__c` | Read. |
| Field | `Setting_Name__c`, `Old_Value__c`, `New_Value__c`, `Changed_By__c`, `Changed_At__c` | Read. |
| Object | `Error_Log__c` | none: the Hub tile shows zero rather than failing. |

## Nonprofit_Read_Only

Same as `Nonprofit_Staff` with one difference: no object or field is writable anywhere, and
the `Nonprofit_Settings` tab stays visible so that a board member or a bookkeeper can see
how the org is configured without being able to change it.

| Kind | Entry | Why |
|---|---|---|
| Application | `Nonprofit_Hub` (visible) | |
| Tab | `Nonprofit_Hub_Home`, `Households`, `Organizations`, `Nonprofit_Settings` | Visible. |
| Custom permission | none | |
| Apex class | the seven classes listed above | |
| Object | `Nonprofit_Settings__c`, `Setting_Change__c` | Read only. |

## Notes for the integrator

- `Setting_Definition__mdt` needs no permission set entry: custom metadata is readable by
  any user with access to the Apex that queries it.
- The Households and Organizations tabs are app pages hosting the standard list view
  component pointed at the `Households` and `Organizations` list views that C-01 ships.
  Those list views need to exist for the pages to render.
- The console writes `Nonprofit_Settings__c` in user mode, so object and field access on
  the custom setting is what actually governs saving, alongside the custom permission.
- C-03 changes one shared file outside its own: `.prettierrc` gains an override keeping
  `*.labels-meta.xml` whitespace strict, because the repository's whitespace-insensitive
  XML rule rewraps long label text and would put line breaks inside user-facing strings.
