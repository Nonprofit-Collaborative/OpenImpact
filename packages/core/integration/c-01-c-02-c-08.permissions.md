# Integration notes: C-01, C-02, C-08 (households, naming, layouts)

For the integrator. This branch does not touch permission set files or the Nonprofit Hub
app. Everything those files need from the household feature is listed here.

## 1. Permission set entries

### Nonprofit_Admin

**Objects (full access)**

| Object | Create | Read | Edit | Delete | View All | Modify All |
|---|---|---|---|---|---|---|
| Account | yes | yes | yes | yes | yes | yes |
| Contact | yes | yes | yes | yes | yes | yes |
| Household_Member__c | yes | yes | yes | yes | yes | yes |

**Fields (read and edit)**

- Account: Household_Formal_Greeting__c, Household_Informal_Greeting__c, Custom_Name__c,
  Primary_Contact__c, Member_Count__c, Anniversary__c, Deceased__c, Household_Role__c,
  Exclude_From_Household_Name__c, Exclude_From_Greetings__c, Preferred_Name__c
- Contact: Deceased__c, Household_Role__c, Exclude_From_Household_Name__c,
  Exclude_From_Greetings__c, Preferred_Name__c
- Household_Member__c: Household__c, Contact__c, Account__c, Role__c, Is_Primary__c,
  Start_Date__c, End_Date__c

Member_Count__c is written by Apex only, but the running user needs edit on it because
every save runs in user mode. Do not mark it read only in any permission set that a user
who edits people or households holds.

**Record types (assigned and visible)**

- Account.Household
- Account.Organization
- Contact.Household_Contact

**Apex classes**

- HouseholdController
- HouseholdService
- HouseholdNamingService
- HouseholdNamingBatch
- HouseholdSelector
- PersonRecordSelector

**Tabs**

- Household_Member__c: Available (admin only; it is a supporting object, not a daily one)

**Page layout assignments**

| Object and record type | Layout |
|---|---|
| Account.Household | Household Layout |
| Account.Organization | Organization Layout |
| Contact.Household_Contact | Household Contact Layout |
| Household_Member__c | Household Member Layout |

### Nonprofit_Staff

Same as Nonprofit_Admin except:

- Objects: Account and Contact create, read, edit (no delete, no View All, no Modify All);
  Household_Member__c create, read, edit (no delete).
- Fields: the same list, read and edit.
- Record types: the same three, assigned and visible.
- Apex classes: HouseholdController, HouseholdService, HouseholdNamingService,
  HouseholdSelector, PersonRecordSelector (not HouseholdNamingBatch: recomputing every
  household belongs with the admin).
- Tabs: Household_Member__c hidden.
- Layout assignments: the same four.

### Nonprofit_Read_Only

- Objects: Account, Contact, Household_Member__c read only.
- Fields: every field listed above, read only.
- Record types: the same three, visible (not defaulted).
- Apex classes: HouseholdController only (the members panel is read only without edit
  access, and the move action fails in user mode as it should).
- Tabs: Household_Member__c hidden.
- Layout assignments: the same four.

## 2. Custom permission

The naming settings component checks `Manage_Nonprofit_Settings`. It is not defined by this
branch. It belongs in Nonprofit_Admin only.

## 3. Custom labels

`packages/core/main/default/labels/CustomLabels.labels-meta.xml` in this branch contains
only this feature's twelve labels, sorted by fullName. Union it with the other branches'
label files rather than replacing either.

## 4. Custom metadata records shipped

- `Naming_Pattern.*` (six records) against the `Naming_Pattern__mdt` type, which this branch
  creates.
- `Setting_Definition.*` (nine records) against the `Setting_Definition__mdt` type, which
  another branch creates. Field names assumed: Setting_Key__c, Section__c, Module__c,
  Data_Type__c, Picklist_Values__c, Component__c, Description__c, Help_Path__c,
  Sort_Order__c.
- `Automation_Registry.ContactTriggerHandler` and `Automation_Registry.AccountTriggerHandler`
  against the `Automation_Registry__mdt` type, which another branch creates. Field names
  assumed: Description__c, Default_Enabled__c, Handler_Class__c, Object__c, Order__c. If the
  real type uses other API names, these two files are the only ones to change.

## 5. Classes this branch calls but does not ship

`TriggerDispatcher`, `TriggerHandler`, `AutomationControl`, `ErrorLogger`, `SettingsService`,
`OrgShapeDetector`, `TestDataFactory`. They were stubbed locally to compile and check this
branch, and the stubs are not committed. The contracts relied on are:

- `TriggerDispatcher.run(TriggerHandler handler)`
- `TriggerHandler` virtual, with `beforeInsert`, `afterInsert`, `beforeUpdate`,
  `afterUpdate`, `beforeDelete`, `afterDelete`, `afterUndelete` all overridable
- `ErrorLogger.log(Exception e, String context)` and
  `ErrorLogger.log(Exception e, String context, Id recordId)`
- `SettingsService.getSettings()` returning `Nonprofit_Settings__c`
- `OrgShapeDetector.detect()` returning an object with a public `Boolean hasPersonAccounts`

## 6. Settings fields this branch reads

All on `Nonprofit_Settings__c`, all already in the canonical model Section 12:
Household_Membership_Mode__c, Auto_Create_Households__c, Delete_Empty_Households__c,
Create_Households_For_Person_Accounts__c, Household_Name_Pattern__c,
Formal_Greeting_Pattern__c, Informal_Greeting_Pattern__c, Include_Deceased_In_Name__c.
